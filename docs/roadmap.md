## Фаза 1 — Первые два контракта

**Цель**: спеки, на которых немедленно строится движок (карточка
`cli-service-management` доски vesma ждёт ровно их).

- [ ] `specs/component-manifest/v1/`: spec.md + JSON-Schema + 3 примера
      (python-модуль / внешний процесс / чужой раннтайм) + conformance-чеклист
- [ ] `specs/service-lifecycle/v1/`: contract супервайзера (start/stop/
      restart/status/health, тиры, рестарт-политики, изоляция)
- [ ] `specs/control-socket/v1/`: путь в лэйауте, протокол CLI↔супервайзер,
      права
- [ ] `specs/layout/v1/`: канонический лэйаут user-профиля (конфиги/
      данные/состояние/кэш/сокеты/venv-дисциплина)
- [ ] Conformance-раннер v0 (исполняемая проверка манифеста по схеме)
- [ ] Каждый контракт: пример-минимум зелёный, схемы валидны, семвер
      проставлен

Спеки — источник; детали реализации и миграционные волны — в движке.

- [ ] Дизайн `vesma service {install,start,stop,restart,status,logs}`

- [ ] ⚠️ Миграция прод-сервера ноутбука — **после 2026-10-16** (B0-окно)
- [ ] Миграция board / mesh / eyes / agent / metrics по манифестам

## Метрики успеха слоя

1. Новый компонент подключается **без единой правки CLI** (только
   манифест + конформанс) — измеряется на первом стороннем компоненте.
2. Ни один новый сервис экосистемы не появляется вне лэйаута/контракта
   (ревью-вопрос «где манифест?»).
3. Ломающее изменение контракта = MAJOR + окно миграции + dual-поддержка,
   ни одного тихого слома (проверяется breaking-детектором).
