# Conformance checklist — component-manifest v1

Человеческий чеклист соответствия **компонента** контракту
`specs/component-manifest/v1/spec.md` (версия 1.0.0-draft.2) — для
интегратора, подключающего компонент к экосистеме. Исполняемый гейт —
зелёный MUST-прогон `conformance/cases.yaml` раннером `tools/conformance`;
чеклист дополняет его тем, что раннер не видит (права файлов, поведение
компонента, операционная гигиена).

| ID | Пункт | Раздел спеки |
|---|---|---|
| CM-01 | Манифест валиден по `schema/component-manifest.schema.json`; ни одного неизвестного поля (strict validation) | §3.2 |
| CM-02 | `apiVersion: vesma.component/v1` присутствует; другие версии не используются до появления их поддержки | §3.2 |
| CM-03 | `metadata.name` по шаблону `^[a-z][a-z0-9-]{0,62}$` и уникален в установке | §3.3 |
| CM-04 | `metadata.version` — SemVer 2.0.0 компонента; `description` ≤ 200 символов | §3.3 |
| CM-05 | `tier` задан (`core` \| `optional`); рестарт-поведение по тиру НЕ дублируется в манифесте — его применяет супервайзер | §3.3 |
| CM-06 | `provenance`: https-URL репозитория + SPDX-лицензия; для бинарей `artifact_sha256` задан и совпадает с поставляемым артефактом | §3.3 |
| CM-07 | Выбран ровно один `kind`; присутствует и корректна только его секция: `launch` (child-process) или `in_process` (in-process) | §3.4 |
| CM-08 | `argv` — список строк без shell-метасимволов, whitespace и `sh -c`; плейсхолдеры только из allowlist `{config_path} {data_dir} {runtime_dir} {venv_bin}` | §3.5 |
| CM-09 | `env.vars` без секретов (по именам тоже); секреты только в `env_file` вне каталога манифестов, права `0600`, владелец — пользователь супервайзера | §3.5 |
| CM-10 | `health`: ровно один блок, соответствующий `checker`; для in-process — `liveness` или `callback`; callback-функция не бросает исключений наружу и возвращает `{state, detail?}` | §3.7 |
| CM-11 | `stop`: компонент реально завершается по `signal` в пределах `grace_period` (проверено на живом компоненте, не декларацией); при `kind: in-process` секции `stop` нет — она запрещена | §3.8 |
| CM-12 | `config`: ровно одна из `schema_file`/`schema_inline` (JSON-Schema 2020-12); текущая конфигурация компонента проходит эту схему | §3.9 |
| CM-13 | `restart`-числа в клампах: `backoff.base` ≥ 500ms, `backoff.max` ≤ 5min, `window.attempts` ≥ 3 — иначе install-валидация отвергнет | §3.10 |
| CM-14 | `depends_on` ссылается только на имена манифестов этой установки; граф ацикличен; зависимость «up» = первый успешный health-проход | §3.11 |
| CM-15 | Манифест написан install-флоу CLI, не руками; компонент не имеет записи в каталог манифестов; `doctor` расхождений не показывает | §3.1 |
| CM-16 | `metadata.name` не входит в зарезервированное множество {`venv`, `venvs`} — коллизия с venv-каталогами лэйаута (specs/layout/v1 §3.8); валидатор отвергает | §3.3 |
| CM-17 | При `tier: core` задан `provenance.artifact_sha256` (hex64, совпадает с артефактом); для `optional` отсутствие хэша — осознанно и видно как `doctor` WARN | §3.3 |

Прохождение: все пункты зелёные + зелёный MUST-прогон `cases.yaml`.
Статус контракта — `draft` до первого конформанса реализации в движке
vesma (ратификация реализацией, ADR-0001 §2).
