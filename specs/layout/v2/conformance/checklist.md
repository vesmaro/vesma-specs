# Conformance checklist — layout v2

Гейт соответствия инсталляции контракту
[spec.md](../spec.md) (версия 2.0.0-draft.1). Тип проверки: **авт** —
исполняемая проверка (тест-пак движка / раннер conformance), **ручн** —
инспекция кода/артефактов. Контракт ратифицируется первым зелёным
прохождением всех применимых пунктов реализацией в движке vesma по
волновому плану ADR-0045 (§6 спеки); волны вводят SY-серию по мере
реализации. На нумерацию LY/SY ссылается threat model спеки (§8);
doctor-проверки DR-xx — §3.14 спеки.

Серии: **LY-01…LY-14** — user-профиль (семантика v1, пути перецелены на
таблицу §3.2), **LY-15/LY-16** — генерации лэйаута, **SY-01…SY-12** —
system-профиль. LY-13 спеки v1 (system-профиль n/a) superseded серией SY.

| ID | Требование | Проверка | Тип | Раздел спеки |
|---|---|---|---|---|
| LY-01 | Права корня user-профиля: `~/.vesma/`, `components.d/`, `env.d/`, `components/` — `0700`, владелец — пользователь; права выставлены явно (не от umask) | тест: создание с «плохим» umask → stat каталогов 0700 | авт | §3.2 |
| LY-02 | Drop-in `components.d/`: имя файла == `metadata.name`; install атомарно пишет (tmp + rename), uninstall удаляет; каждый файл каталога — валидный манифест; env_file манифестов вне `components.d/` | тест: install/uninstall двух компонентов (чужие файлы не тронуты); фикс-манифест с невалидным соседом → отказ загрузки | авт | §3.7 + CM §3.1 |
| LY-03 | env.d: `env.d/<name>.env` — `0600`, владелец — пользователь; fail-closed загрузка: не `0600` / чужой владелец / объявлен и отсутствует = отказ старта с готовой командой (`ENV_FILE_UNSAFE`) | тесты: старт с правами 0644, с чужим владельцем, с удалённым файлом → отказ + команда в диагностике | авт | §3.7 + CM §3.5 |
| LY-04 | Данные `~/.vesma/components/<name>/` — `0700`, владелец; default cwd ребёнка = `{data_dir}`; `cwd` манифеста по умолчанию — каноническое значение install-флоу | тест: spawn → `/proc/<pid>/cwd` == data-каталог; stat каталога | авт | §3.2, §3.6 |
| LY-05 | venv-уникальность: `~/.vesma/venvs/<name>/` — `0700`, ровно один venv на python-юнит; два компонента на одном venv = ошибка install-валидации; имена против реестра зарезервированных | тест: инсталляция in-process + python-ребёнок + не-python-ребёнок → ровно один `venvs/`; имя из реестра → отказ | авт | §3.2-e, §3.10 |
| LY-06 | venv integrity (user): site-packages не миро- и не группо-записываемы, владелец совпадает, `pip freeze` == lock (дрейф = FAIL) | тест: chmod 0777 site-packages → FAIL; ручная установка пакета → FAIL с командой | авт | §3.10, DR-02 |

| LY-08 | Пин-политика: зависимости `==` против lock; источники — только PyPI | проверка lock-файла install-флоу; URL-зависимость → reject | авт | §3.10 |
| LY-09 | Единственность мест логов (user): systemd → только journald; не-systemd → только `~/.vesma/logs/<name>/` (ротация 10 MB × 5); `/var/log/vesma` не существует; двойная запись запрещена | тест A (systemd): journalctl-фильтр находит строки, файловых логов нет; тест B (контейнер): ротация; скан на «третьи места» | авт | §3.9 |
| LY-10 | history: `~/.vesma/history/` — `0700`, append-only | тест: переходы FSM дописывают в конец; попытка перезаписи → инвариант | авт | §3.9 |
| LY-11 | Runtime: `${XDG_RUNTIME_DIR}/vesma/` — `0700`, `control.sock` — `0600`; пустой/непригодный `XDG_RUNTIME_DIR` → fallback `~/.vesma/run/` + WARN | тест: старт с XDG_RUNTIME_DIR и с очищенным (путь + WARN); stat сокета | авт | §3.8 + CS §3 |
| LY-12 | Кэш: `~/.vesma/cache/<name>/` — `0750`; запись только через taint-API; значение из env-файла → отказ API; rm -rf кэша безопасен | тест: probe-запись значения env-файла → отказ; удаление кэша → компонент работает | авт | §3.11 |
| LY-13 | Плейсхолдеры v2: `{config_path}`/`{data_dir}`/`{runtime_dir}`/`{venv_bin}` расширяются по таблице §3.6; иных подстановок нет; `{venv_bin}` без venv = fail-closed | тест: spawn фикс-манифестов с каждым плейсхолдером → путь из таблицы; ссылка без venv → отказ | авт | §3.6 |
| LY-14 | Doctor: находки DR-01…DR-19 несут severity и готовую команду; doctor не исполняет команды сам | тест: инжекция находок → команда в выводе; инсталляция не мутируется | авт | §3.14 |
| LY-15 | Pin-тест генерации v1.5: инсталляция с меткой v1.5 резолвит пути по таблицам v1 (zero-regression) — весь набор LY-01…LY-14 зелёный на v1.5-путях | тест: фикстура v1.5-формы → полный user-набор зелёный | авт | §3.3 |
| LY-16 | Запрет смешанной записи: движок не пишет в v1.5-пути v2-инсталляции и наоборот; смешанное дерево = doctor FAIL | тест: инъекция чужого артефакта → DR-17 FAIL | авт | §3.3, DR-17 |
| SY-01 | Профиль и изоляция: `install --system` создаёт system-инсталляцию с меткой профиля; user и system на одном data-root = doctor FAIL (DR-14, «ERROR» вердикта) | тест: инсталляция --system → метка; коллизия data-root → FAIL | авт | §3.1, DR-14 |
| SY-02 | FHS-манифест: единственный файл; инсталлятор, юниты и дерево сверяются с ним; хардкод путей мимо манифеста отсутствует | инспекция кода/юнитов + тест сверки дерева с манифестом | авт/ручн | §3.12 |
| SY-03 | Права system-дерева: `/etc/vesma` `0750 root:vesma`, файлы `0640 root:vesma`; `env.d` файлы `0600` (дрейф = FAIL — гейт вердикта); `/var/lib/vesma` `0750 vesma:vesma`, БД `0600`; кэш/логи `0750` | тест: установка → stat-обход по таблице §3.4; chmod 0644 env.d-файла → DR-15 FAIL | авт | §3.4, DR-15 |
| SY-04 | Сервисный аккаунт: sysusers.d-фрагмент создаёт vesma:vesma (idempotent); home `/var/lib/vesma`; shell-вход запрещён | тест: повторный install не дублирует аккаунт; инспекция фрагмента | авт | §3.4, §3.13 |
| SY-05 | Conffile-зона: обновление не перезаписывает молча операторскую правку `config.yaml`/`components.d/`; правка уходит в backup, оператор получает выбор | тест: правка + повторный install → backup + сохранение правки | авт | §3.7 |
| SY-06 | Логи system: journald primary; `/var/log/vesma/` не создаётся без opt-in; opt-in не включает двойную запись | тест: установка без opt-in → каталога нет; с opt-in → ровно один режим | авт | §3.9 |
| SY-07 | venv-ревизии: `venvs/<name>` — симлинк на `<name>-<rev>/` внутри `/usr/lib/vesma/venvs/`; дерево `0755 root:root`; симлинк наружу = DR-16 FAIL; freeze активной ревизии == lock | тест: обновление → атомарный swap; инъекция внешнего симлинка → FAIL | авт | §3.10, DR-16 |
| SY-08 | Материализация venv: `uv venv` + wheel той же сборки; pip-as-root отсутствует; чужие venv не пишутся | инспекция кода установщика + тест: wheel-версия == версия установщика | авт/ручн | §3.10, §3.13 |
| SY-09 | install-state и exact-inverse uninstall: каждый артефакт записан; uninstall удаляет ровно записанное в обратном порядке; дрейф state ↔ ФС = громкий отказ; чужие файлы не тронуты | тест: install → uninstall → дерево чисто, чужой файл рядом жив; инъекция дрейфа → отказ | авт | §3.13, DR-17 |
| SY-10 | Юниты: system-юнит `/etc/systemd/system/vesma.service` (`0644 root:root`) == регенерированному; user-юнит: канон `~/.vesma/systemd/user/` == установленному в `~/.config/systemd/user/`; сосуществование без префиксов | тест: daemon-reload + статусы обоих юнитов; дрейф → DR-18 FAIL | авт | §3.8, DR-18 |
| SY-11 | IPC system: `/run/vesma/` создан юнитом (`RuntimeDirectoryMode=0750`); сокет — control-socket v1 §3; user-IPC при этом не затронут | тест: старт system-юнита → stat `/run/vesma`; user runtime не изменён | авт | §3.8 |
| SY-12 | Генерация и advisory: doctor помечает v1.5-инсталляцию DR-19 advisory с командой консолидации; консолидация переносит venv/кэш/стек в `~/.vesma` без потери данных (staging → verify → publish) | тест: консолидация фикстуры v1.5 → зелёный doctor, данные целы | авт | §3.14, §9.2 |

Пункты SY-xx исполняются и чеклятся волнами 2–4 плана ADR-0045
(install --system → doctor/update → мовер). Прохождение user-пунктов
(LY-01…LY-16) фиксируется реализацией волны 1 (резолвер + pin-тесты);
отсюда берётся ратификация статуса контракта `2.0.0`.
