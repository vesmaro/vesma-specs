# Service Lifecycle v1 (Supervisor Contract) — Quickstart

This contract defines the behavior of the **vesma supervisor** — the single long-lived process that owns the
lifecycle of every component on the machine: spawn, health, restart, stop, observability. The `vesma` engine
implements it; this contract is the requirements source and the conformance gate. Component inputs come from the
[component manifest](../../component-manifest/v1/spec.md); live management goes through the
[control socket](../../control-socket/v1/README.md).

## Normative spec

[spec.md](spec.md) — normative text (Russian canon, RFC 2119): process model, child FSM (transitions T1–T14),
structural observability lines, restart policies, systemd unit template plus hardening block, mini-STRIDE threat model.

Full English mirror: [spec.en.md](spec.en.md).

## Key rules

- **Isolation** — a child crash, any subset of children, never kills the supervisor or the control socket; control availability is an invariant.
- **`core` restarts forever** — exponential backoff 1s ×2, cap 30s, ±20% jitter; the counter resets after 300s of continuous uptime; a crash-loop (10 attempts without healthy) sets global health to `degraded` + one alert line, restarts continue.
- **`optional` runs on a budget** — 5 attempts per 300s window, then `degraded` + health flag + exactly one ERROR line; afterwards a lazy retry every 300s with no alert spam; a manual start resets the budget.
- **Stop is group-scoped and graceful** — SIGTERM to the child's process group (`kill(-pgid, …)`), then SIGKILL of the group after the manifest grace period; `pkill`-style inventory by name is forbidden anywhere.
- **Exactly ONE systemd unit** over the vesma process, generated by `vesma service install`: `ExecStart` is the static supervisor launch line (no component argv, no `sh -c`; children spawn via the execve array from `launch.argv`), no `ExecStop` is generated (the default SIGTERM is the contract stop); systemd never knows about the children.
- **Children get a clean environment** — `env -i` semantics: a constructed PATH + manifest `env.vars` + `env_file`; no host environment leakage.
