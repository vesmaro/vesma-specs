# Conformance checklist — service-lifecycle v1

Гейт соответствия реализации супервайзера контракту
`specs/service-lifecycle/v1/spec.md` (версия 1.0.0-draft.1).
Тип проверки: **авт** — исполняемая проверка (pytest-пак движка / раннер
conformance), **ручн** — инспекция кода/артефактов. Контракт ратифицируется
первым зелёным прохождением всех пунктов реализацией в движке vesma.

| ID | Требование | Проверка | Тип | Раздел спеки |
|---|---|---|---|---|
| SL-01 | Изоляция: `kill -9` произвольного подмножества детей оставляет супервайзер и контрольный сокет живыми; дети уходят в backoff по политике тира | сценарий: спавн N детей, SIGKILL подмножества, assert supervisor alive + socket accepts + FSM-строки | авт | §3.2 |
| SL-02 | Исключение в per-child коде ловится на границе; main loop не умирает никогда | тест-инъекция падающего per-child обработчика; assert main loop жив, FSM → backoff | авт | §3.2 |
| SL-03 | Каждый ребёнок в собственной сессии: pgid == pid (start_new_session=True) | проверка `/proc/<pid>/stat` (field 5) после spawn | авт | §3.1 |
| SL-04 | Стоп группы: `kill(-pgid, SIGTERM)` → grace period → `kill(-pgid, SIGKILL)` группы; pkill отсутствует в путях остановки и в сгенерированном юните | потомок-«упрямец» в группе переживает SIGTERM, умирает с группой по SIGKILL; grep кода и юнита на pkill | авт + ручн | §3.1, §3.5 |
| SL-05 | Subreaper установлен (`PR_SET_CHILD_SUBREAPER, 1`); осиротевший внук репарентится в супервайзер и reap'ится, зомби не остаётся | сценарий: ребёнок спавнит внука и умирает; assert внук reaped супервайзером (нет зомби в `/proc`) | авт | §3.1 |
| SL-06 | PID1-режим: SIGTERM/SIGINT обработаны; осиротевший внук reap'ится; все дети остановлены graceful ДО exit | запуск бинарника как PID1 в контейнере; инъекция осиротевшего внука; signal → graceful-порядок → exit 0 | авт | §3.1 |
| SL-07 | FSM: все переходы T1–T14 реализованы; запрещённые переходы невозможны | матрица переходов из spec.md прогоняется фаззером событий (spawn/exit/health/stop) | авт | §3.3 |
| SL-08 | Структурные строки spawn/exit/health/degraded соответствуют грамматике §3.4 (префикс, порядок полей, код/сигнал взаимоисключающи) | regex-парсер всех строк журнала прогона; нулевые расхождения | авт | §3.4 |
| SL-09 | Optional: при исчерпании бюджета — состояние degraded + health-флаг + РОВНО ОДНА ERROR-строка `reason=restart-budget-exhausted attempts=5 window=300s` | подсчёт ERROR-строк в журнале прогона == 1 | авт | §3.5 |
| SL-10 | Lazy-retry optional: раз в 300s, БЕЗ новых ERROR-строк (алерт-спама нет); ручной `vesma service start --component=X` сбрасывает бюджет | тайминг попыток ±допуск; подсчёт ERROR после входа в lazy-режим == 0; ручной старт → бюджет чист | авт | §3.5 |
| SL-11 | Core crash-loop: 10 попыток без healthy → глобальный health=degraded + алерт-строка `reason=crash-loop attempts=10 window=none`; рестарт продолжается | прогон до 10-й попытки; assert глобальный флаг + строка + продолжение рестартов | авт | §3.5 |
| SL-12 | Core backoff: base 1s, ×2, cap 30s, jitter ±20%; счётчик сбрасывается после 300s непрерывного uptime | замер интервалов с допуском; uptime-тест сброса | авт | §3.5 |
| SL-13 | Env-семантика: env ребёнка == конструируемый PATH + `env.vars` + `env_file`; ни одной хостовой переменной сверх allow-list | conformance-ребёнок печатает своё окружение; раннер сверяет allow-list (урок 401-шторма) | авт | §3.2 |
| SL-14 | Контрольный сокет: fd не наследуется детьми, путь отсутствует в env; `/proc/<pid>/fd` ребёнка не содержит сокета | проверка fd-таблицы и env всех детей после spawn | авт | §3.2, §7 |
| SL-15 | Порядок старта: топологический по depends_on; цикл = ошибка install-валидации; зависимые при неподнятой core-зависимости — state=blocked с backoff-логами | install-манифест с циклом → ошибка; старт с мёртвой core-зависимостью → blocked; log-строки присутствуют | авт | §3.5, §3.3 |
| SL-16 | Graceful-остановка: реверс-топологический порядок (зависимые раньше зависимостей); выход супервайзера только после reaping всех детей | SIGTERM супервайзеру; порядок stop-строк по журналу; assert отсутствие живых детей/зомби на момент exit | авт | §3.5 |
| SL-17 | Юнит-шаблон: все директивы таблицы MUST присутствуют; ExecStart — одна строка без `sh -c`; ExecStop отсутствует; `StartLimit*` валидны | парсер сгенерированного юнита против эталонной таблицы | авт | §3.6 |
| SL-18 | Hardening-блок полный; в контейнерах — только громкие задокументированные деградации (install-вывод + status); клампы restart-override: base ≥ 500ms, max ≤ 5min, attempts ≥ 3 | сравнение юнита с hardening-таблицей; манифест с out-of-clamp числами → ошибка install-валидации | авт + ручн | §3.6, §3.5 |

Прохождение: все 18 пунктов зелёные на целевых профилях (bare / distrobox /
podman — smoke-матрица для Tier B включения `SystemCallFilter`). Статус
прогона фиксируется реализацией в движке; отсюда берётся ратификация
статуса контракта `1.0.0`.
