# ADR-0001: структура репозитория и governance спек-слоя

- **Status**: accepted
- **Date**: 2026-10-04
- **Deciders**: учредительный АрхКом VESMA (позиции: архитектор, SRE/DevOps, backend, безопасность); владелец — санкционировал создание репозитория и директивы-входы
- **EN mirror**: [0001-repo-structure-and-governance.en.md](0001-repo-structure-and-governance.en.md) — информативный перевод; нормой является русская версия

## Context

До 2026-10-04 экосистема VESMA управляла компонентами ad hoc: пять механизмов
запуска сервисов, `pkill`-паттерны в `ExecStop`, конфиги в легаси-именах,
venv-перекрытия. Каждому компоненту — собственная обвязка, каждой волне —
собственный механизм. Три директивы владельца от 2026-10-04 фиксируют
противоположный принцип:

1. **CLI-first** — единый CLI `vesma`; юниты systemd генерирует CLI,
   `ExecStart` — одной строкой без `sh -c`, `ExecStop` без `pkill`.
2. **Супервайзер-архитектура** — один процесс-супервайзер, ядро против
   optional-компонентов, деградация вместо падения, контрольный unix-сокет.
3. **Единый контрактный интерфейс** — CLI не дописывается под компонент:
   компонент = манифест + конформанс.

Чтобы это работало, правила приёма компонентов должны быть декларативными и
общими. Этот репозиторий — дом таких правил, и учредительный АрхКом должен
был решить, как он устроен: каталоги, дисциплина версий, кто мержит, как
исполняется conformance, какие языки и какая политика секретов.

Слой specs отделён от canon (правило границы: «КАК соединяются → specs;
ЧТО обещано до измерения → canon»), репозиторий публичен под Apache-2.0 и
служит витриной для внешних интеграторов. Это добавляет два ограничения:
дисциплина секретов обязательна, а интеграторская часть документации должна
читаться без знания внутреннего контекста экосистемы.

Повестка и нерушимые входы сессии — [бриф учредительного АрхКома](../docs/brief-2026-10-04-archcom-founding.md);
вердикты ниже зафиксированы по его итогам и не переигрываются без владельца.

## Decision

### 1. Структура: spec-на-контракт

```
specs/<name>/vN/
  spec.md           # нормативная спека (русский, требования по RFC 2119)
  spec.en.md        # информативное EN-зеркало спеки (single-commit sync)
  README.md         # EN quickstart для интегратора
  schema/           # машинные схемы (JSON-Schema и др.)
  examples/         # примеры-минимум (обязательны к мержу)
  conformance/      # conformance-сьют контракта
  CHANGELOG.md      # SemVer-история контракта
adrs/               # ADR-NNNN — вердикты и решения слоя (на корне)
tools/conformance/  # conformance-раннер
tools/ci/           # три инструмента: линт схем, breaking-детектор, bilingual-проверка
templates/          # шаблоны: спека, манифест компонента, conformance-сьют
GLOSSARY.md         # глоссарий: термин EN — определение RU
ECOSYSTEM.md        # карта компонентов экосистемы
```

Правила неизменности:

- каталог версии `vN/` иммутабелен после стабилизации версии: правки текста,
  меняющие смысл, — только через новую версию;
- минорные (аддитивные, не ломающие) изменения фиксируются в шапке `spec.md`
  и `CHANGELOG.md` без заведения нового каталога;
- `adrs/` стоит на корне: вердикты АрхКома — первичный артефакт слоя рядом со
  спеками, а не приложение в `docs/`.

### 2. Дисциплина контрактов: SemVer и окно устаревания

- Каждому контракту — свой SemVer; `1.0.0` = первый стабильный.
- Breaking-change-детектор в CI: сравнение схем новой версии с предыдущей.
- Deprecation-окно = `max(90 дней, 2 минорных релиза контракта)`; для версий
  до `1.0` — 14 дней.
- В течение окна действует dual-поддержка обеих `vN`; удаление старой версии —
  только в MAJOR. Прецедент дисциплины: dual-переход schema 2, ADR 0003
  vesma-cortex.

### 3. Governance

- Мержит Chair АрхКома (TL).
- Кворум АрхКома ≥ 2, включая владельца зоны, — для: новых контрактов,
  MAJOR/breaking-изменений, deprecation.
- Аддитивные минорные поля — TL + уведомление комитета, без созыва кворума.
- Проза, примеры, tools — TL после ревью.
- `CODEOWNERS` на `specs/`, `adrs/`, `tools/`.
- Вердикт АрхКома = ADR + PR, неразделимы: решение без зафиксированного ADR
  и влитого PR не существует.

### 4. Conformance-гейт

- CI гоняет conformance-раннер на каждый PR, затрагивающий `specs/**`.
- Интеграция компонента в экосистему = зелёный MUST-прогон его сьюта.
- Раннер: stdlib + `jsonschema`; валидирует только декларации (манифесты,
  схемы, сьюты) и не исполняет компоненты. Исполнение компонентов — забота
  супервайзера и его контрактов, не раннера.

### 5. i18n

- `spec.md` и ADR — русский (канон экосистемы), термины и идентификаторы — EN.
- `README.md` контракта — EN quickstart: как подключиться, что реализовать,
  чем проверить.
- Правило: «что интегратор делает — EN; что АрхКом решил — RU».

> **Поправка (2026-10-05, директива владельца о полной двуязычности
> публичной репы).** Каждый контракт несёт информативное EN-зеркало
> `spec.en.md` (single-commit sync; при расхождении приоритет у русской
> версии); парность механически гейтится CI (bilingual sync check).
> Отклонённая ниже альтернатива касалась полноценного нормативного
> EN-пере-авторства спек — зеркала её не нарушают.

### 6. Секретная политика публичного репозитория

- Never-list: токены, connection strings, реальные пути и hostname'ы машин
  владельца, коммиченые `.env`.
- В примерах — только плейсхолдеры (`<token>`, `example.org`).
- `gitleaks` в CI.
- Инцидент с секретом = **rotate first**, разбор после.

## Alternatives considered

| Альтернатива | Почему отклонена |
|---|---|
| Единый корневой CHANGELOG вместо CHANGELOG на контракт | релизы контрактов независимы: общий журнал дрейфует и перестаёт отвечать на вопрос «что изменилось в этом контракте» |
| `docs/adr/` вместо корневого `adrs/` | понижает статус первичного артефакта: ADR здесь — не приложение к документации, а равноправный продукт слоя |
| Аддитивные минорные поля всегда через кворум АрхКома | тормозит эволюцию контрактов. Диссент системного инженера записан: при дрейфе «аддитивных» полей в ломающие — возвратная точка, кворум возвращается |
| pytest-пак как публичная форма conformance-раннера | публичная репа должна исполняться на голой машине без установки тестового фреймворка; stdlib + `jsonschema` дают это из коробки |
| Полный EN-перевод спек в v1 | дрейф двуязычности: два нормативных текста неминуемо расходятся; норматив один (RU), EN — quickstart |
| JSON-RPC 2.0 как протокол контрольного сокета | цена поддержки выше пользы для локального управления; смежный вердикт спеки control-socket (v1), здесь упомянут для полноты |

## Consequences

**Позитивные.** Структура предсказуема для внешних интеграторов: контракт
ищется по имени, версия — по каталогу. Conformance-гейт делает принцип
«подключение без правок CLI» проверяемым, а не декларативным. Governance
разделяет эволюцию (аддитивная, лёгкая) от ломающих изменений (кворум, окно,
dual-поддержка).

**Обязательства.** Движок `vesma` и компоненты потребляют спеки фазы 1:
`component-manifest`, `service-lifecycle`, `control-socket`, `layout`
(см. [roadmap](../docs/roadmap.md), фаза 1). CI-гейты (линт markdown,
breaking-детектор, conformance-раннер, `gitleaks`) обязательны до мержа
контрактов — без них гейт не существует.

**Возвратные точки.** Числа рестарт-политик калибруются после B0-окна
телеметрии: миграция прода на супервайзер-архитектуру — строго после
2026-10-16. Записанный диссент по аддитивным полям — возвратная точка
governance при дрейфе.

**Горизонт v2** (сознательно за пределами этого ADR): реализация system scope
лэйаута, групповая модель доступа к контрольному сокету, подписи артефактов,
`sd_notify`, resource limits, `SystemCallFilter`, полный EN-перевод спек.
