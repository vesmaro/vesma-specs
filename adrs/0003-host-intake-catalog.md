# ADR-0003: явный каталог сбора как контракт host-intake v0

- **Status**: accepted
- **Date**: 2026-10-28
- **Deciders**: директива владельца 2026-10-28 — два пункта (per-harness
  re-key моделей; явный контракт поверхности сбора) — санкционировала
  контракт и его гейт-решения (FC-6+FC-7 эта волна; FC-8/9 — DEFERRED
  v2; loopback-probe утверждён; dual-form emission утверждён); бриф TL —
  скоуп и структура спек-волны; стороны полномочий текста — агентный
  драфт контракта (vesma-agent, feat/host-intake-contract) и
  перенесённые красные линии security-verdict (832cd7a)
- **EN mirror**: [0003-host-intake-catalog.en.md](0003-host-intake-catalog.en.md)
  — информативный перевод; нормой является русская версия

## Context

Пункт 1 директивы владельца 2026-10-28 вскрыл дефект v6-ноги (AGW-25):
standalone-таблица моделей искала конфиги, detached от inventory, и
давала НОЛЬ строк на реальном флоте — проверено живьём 2026-10-28 на
core-51: четыре v6 конфиг-файла не существуют, при этом zcode/copilot —
харнесы, которые агент действительно находит, — несут каталоги моделей в
frontmatter определений агентов (рендер fleet `models.yaml` от
GCW-инсталлера). v6-дизайн superseded; его красные линии и дисциплины
переносятся verbatim.

Пункт 2 той же директивы поднял планку: поверхность сбора агента должна
быть ЯВНЫМ контрактом — каждый класс фактов, который агент собирает на
хосте, перечислен; это одновременно поверхность доверия пользователя
(владелец видит полный список «что агенты собирают») и планка полноты
(флот получает максимум полезного объёма фактов в пределах этих границ).
До этого момента «что собирает агент» жил рассеяно по аддендумам
протокола (v1–v6) и не был ни полным, ни диффабельным, ни предъявляемым
пользователю.

Агентный драфт контракта (`docs/design/host-intake-contract-draft.md`,
vesma-agent, feat/host-intake-contract) зафиксировал каталог FC-1…FC-9,
принципы P1–P6 и открытые вопросы OQ-1…OQ-5; гейты драфта утверждены
владельцем: FC-6+FC-7 — в первой волне, FC-8/FC-9 — DEFERRED в v2,
loopback-probe (включая harness-настроенные base_url) — утверждён,
dual-form emission — утверждён.

## Decision

1. **Завести контракт `specs/host-intake/v0/`** (`0.1.0-draft`, статус
   draft): RU-норматив + EN-зеркало + EN quickstart + примеры +
   конформанс-скелет + CHANGELOG, по полному скелету spec-template
   (ADR-0001 §1).
2. **Каталог = поверхность доверия/прозрачности.** §3.2 спеки — закрытый
   перечень классов фактов; не названное — не собирается; добавление
   класса = поправка с гейтом владельца (P1). Каждое поле провода
   отображается ровно на один FC-id; борда рендерит «что агенты
   собирают» ИЗ текста контракта, по version handshake (P6).
3. **FC-6 нормативно в host-intake**: per-harness re-key (строки только
   для обнаруженных харнесов — структурно), per-harness layout-таблица
   (zcode/copilot frontmatter `model:`/`tier:` — grounded 2026-10-28;
   codex/continue/claude-code/aider — v6 перенесено; pi — auth-маркерная
   строка provider `pi` с пустым `models[]`; gemini/qwen — отсутствуют),
   документированные провайдерные формы строк (dual-form emission,
   never guess), probe: фиксированная loopback-таблица + ≤8
   harness-настроенных base_url (анонимно, никогда credentialed —
   вердикт H3), красные линии v6 — verbatim.
4. **FC-7 нормативно в host-intake**: аддитивный top-level элемент
   `mcp_servers` — `{harness, exec_env, servers[] ≤30 sorted, count =
   полный итог}`; имена + transport kind из документированных
   кэшей/конфигов; pi `mcp-cache.json` — только имена (значения никогда
   не декодируются); knob `discovery_models` общий с FC-6.
5. **FC-8/FC-9 — каталогизированы, DEFERRED (v2)**: решение владельца
   записано; реализация — отдельная волна классов; активация = минор
   host-intake с гейтом.
6. **`sessions[]` — вне поверхности агента**: поле discovery-отчёта
   наполняется eyes-сканером борды (ME-062; kora-scan ingest;
   синтетический executor id `hermes`); агент session-фактов не
   конструирует (проверено 2026-10-28 в коде агента и борды); спека
   записывает это честное отсутствие (P4).
7. **Поправка agent-discovery до 0.1.0-draft.2**: re-key населения поля
   `models` (standalone-таблица superseded), probe-расширение,
   FC-7-элемент; форма строки §3.2 и обязанности борды §3.11 не
   менялись — провод аддитивен, старые борды конформны. Релизнутая
   версия не перенумеровывается: draft.2 внутри draft-статуса.
8. **Волны**: спека (эта) → агентная волна v7 (AGW-26,
   feat/host-intake-contract: re-key + FC-7, release v0.11.0, fleet
   update) → борд-зеркальная волна vesma-eyes (ingest + рендер
   прозрачности).

## Alternatives considered

| Альтернатива | Почему отклонена |
|---|---|
| Оставить «что собирает агент» в аддендумах PROTOCOL.md | поверхность пересекает компоненты (агент → борда → рендер пользователю) и должна быть публичной, версионированной и диффабельной; правило слоя «КАК соединяются → specs» (ADR-0001) прямо требует дом здесь; аддендумы — история, не живой норматив |
| Неявная поверхность + ретроспективный аудит кода | нарушает пункт 2 директивы: без явного списка владелец не может увидеть полный перечень собираемого, а ревью «по коду» не масштабируется и не предъявляется пользователю; явный каталог делает дрейф кода от каталога наблюдаемым через рендер прозрачности |
| Собрать FC-8/FC-9 в первой волне | решение владельца на гейте драфта — deferred: ценность реальна (честность ростера/ml-routing), но волна и так несёт re-key ядра + новую ногу; каталогизация без активации даёт планку v2 без риска волны |
| Расширять standalone-таблицу v6 новыми харнесами | лечит симптом, не болезнь: таблица, detached от inventory, снова даёт строки там, где харнес не обнаружен, и ноль — там, где каталог живёт в frontmatter; per-harness re-key делает невозможное невозможным по построению |

## Consequences

**Позитивные.** У поверхности сбора появился экосистемный дом: полный
публичный список «что агенты собирают», карточки FC-id для рендера
бордой, диффабельность по релизам; v6-нулевые строки заменены grounded
per-harness населением; FC-7 даёт флоту honest-аудит MCP-серверов
(роутинг и инвентарь без содержимого); волна v7 получает готовую спеку
вместо обратного инжиниринга.

**Обязательства.** Агент обязан держать код в точном соответствии с
каталогом (дрейф = дефект, видимый через карту поле → FC-id); расширение
per-harness таблицы и активация DEFERRED классов — минорные изменения с
трассировкой; удаление именованного поля — MAJOR. Борд-зеркальная волна
обязана реализовать рендер прозрачности из текста контракта с version
handshake — иначе P6 остаётся планкой на бумаге.

**Возвратная точка.** Если владелец изменит решение по FC-8/FC-9 или по
границам каталога — изменения входят через SemVer-процесс host-intake
(гейт владельца на каждый добавляемый класс), а не молчаливой переписью.
