# Глоссарий VESMA

Посев терминологии спек-слоя: термин EN — определение RU. Термины
определяются здесь один раз; спеки ссылаются на глоссарий и не
переопределяют их. Термины и идентификаторы в текстах спек — EN, проза — RU
(правило i18n: [ADR-0001 §5](adrs/0001-repo-structure-and-governance.md)).

| Термин | Определение |
|---|---|
| **Component** | Единица экосистемы VESMA, подключаемая к супервайзеру по контракту: in-process модуль или child-process. Компонент = манифест + конформанс; CLI под него не дописывается. |
| **In-process module** | Компонент, исполняемый внутри процесса супервайзера как импортируемый модуль (например, python). Живость отдаётся через договорённый интерфейс модуля; отдельного endpoint'а нет. |
| **Child-process** | Компонент-отдельный процесс, запускаемый супервайзером по `launch`-секции манифеста (argv без shell-обёрток) и останавливаемый graceful-сигналом. |
| **Supervisor** | Процесс `vesma`, владеющий жизненным циклом всех компонентов: запуск, health, рестарт по тирам, деградация optional вместо падения системы. Управление — через контрольный сокет. |
| **Manifest** | Декларативное YAML-описание компонента (apiVersion, kind, metadata, launch/in_process, health, stop, config, restart, depends_on). Единственный источник знаний CLI о компоненте. Шаблон: `templates/manifest-template.yaml`. |
| **Tier (core / optional)** | Критичность компонента. `core` обязателен для работы системы (ядро = сервер памяти + API); `optional` при отказе деградирует: health-флаг + подсветка + алертинг, система жива. |
| **Health check** | Декларация в манифесте, по которой супервайзер судит о живости компонента: проба endpoint'а/порта, наблюдение процесса или интерфейс in-process модуля. |
| **Grace period** | Окно времени после graceful-сигнала остановки, в течение которого компонент обязан завершиться; по истечении супервайзер эскалирует. |
| **Restart policy / backoff** | Политика перезапуска: core рестартует всегда с backoff (нарастающая задержка до потолка); optional — N попыток, затем down + health-флаг + алерт. Числа — контрактные дефолты v1 (specs/service-lifecycle/v1 §3.5); пересмотр — только SemVer-процессом; первое окно наблюдения — вход ратификации статуса, не приостановка нормы. |
| **Control socket** | Контрольный unix-сокет супервайзера (docker-паттерн): канал CLI ↔ живой процесс для status/logs/start/stop/restart по манифестам. Права `0600`, user scope. |
| **Conformance** | Исполняемая проверка соответствия компонента/декларации контракту vN: сьют `must`/`should`-случаев, исполняемый раннером `tools/conformance` (stdlib + `jsonschema`). Зелёный MUST-прогон — гейт интеграции. |
| **Canonical layout** | Deb-подобная дисциплина каталогов экосистемы: где конфиги, данные, состояние, кэш, сокеты и venv каждого компонента. Контракт `layout` (фаза 1). |
| **Runtime directory** | Каталог живого состояния работающего супервайзера внутри лэйаута: сокеты, pid-файлы и прочее, что существует только во время исполнения. |
| **venv discipline** | Один управляемый venv на компонент внутри лэйаута, `PYTHONNOUSERSITE=1`, doctor-проверки перекрытий. Ответ на боль venv-перекрытий легаси-инсталляций. |
| **Decision provider** | Сменная реализация интерфейса «семантический if»: отвечает на типизированный вопрос продукта по подготовленному canon-состоянию. Провайдер — не компонент супервайзера (манифест не заводится). Контракт `decision-provider` v1 (мигрирован из canon ADR-0004). |
| **Choice / Score / Noul** | Три примитива решения: `Choice` — выбор варианта по заданным критериям; `Score` — оценка на упорядоченной шкале; `Noul` — калиброванное «да/нет»; каждый ответ — с уверенностью. Новые примитивы — аддитивное изменение контракта (минор). |
| **Prepared canon-state** | Подготовленное canon-состояние: конверт + тело выбранных записей, собранное под конкретный запрос; единственная разрешённая форма входа провайдера решений (сырые дампы запрещены). |
| **Fail-open degradation** | Семантика отказа провайдера решений: ошибка провайдера переключает работу на baseline и никогда не блокирует продуктовый путь; каждая деградация — громкий машинно-парсируемый warn с классом действия из контракта. |
| **Baseline implementation** | Реализация (a) `deterministic` — детерминированные эвристики движка, формализованные как первая реализация интерфейса; база калибровки остальных реализаций и цель деградации. |
| **Calibration gate** | Гейт «калибровка до доверия»: не-базовая реализация провайдера решений не участвует в продуктовых решениях до прохождения калибровки по методологии canon (vitals); локальность льгот не даёт. |
| **Attribution** | Указание в каждом ответе и в журнале, кто ответил: примитив, реализация, уверенность (телеметрия машино-парсируема). |
| **Breaking change** | Изменение контракта, ломающее совместимость с потребителями: по SemVer требует MAJOR и deprecation-окна с dual-поддержкой. Детектируется breaking-детектором CI. |
| **Deprecation window** | Переходный период, в котором старая версия контракта живёт рядом с новой: `max(90 дней, 2 минорных релиза)`, для версий до 1.0 — 14 дней; удаление старой — только в MAJOR. |
| **ADR** | Architecture Decision Record: запись архитектурного решения с контекстом, решением, отклонёнными альтернативами и последствиями. Не удаляется — supersede. Дом: `adrs/` (ADR-0001). |
